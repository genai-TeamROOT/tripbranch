# 세대 비교 실험 결과 — `gemini-3.5-flash-lite` 추가

| 항목 | 값 |
|---|---|
| 실행일 | 2026-08-12 |
| 상태 | **완료 — 판정: 유망하나 채택 전 확인 필요** |
| 선행 실험 | `../fallback_model_ab_2026-08-12/`, `../fallback_thinking_2026-08-12/` |
| 신규 대상 | `gemini-3.5-flash-lite` |
| 측정 도구 | `backend/scripts/measure_intent_thinking.py` |

---

## 1. 한 줄 요약

**`gemini-3.5-flash-lite`는 2.5-flash보다 빠르면서 정확도가 거의 같다.** 규칙 정의 65건
기준 63/65로 2.5-flash(64/65)에 1건 차이고, 지연 중앙값 852ms는 2.5-flash(1,588ms)의
절반이며 꼬리는 최대 1,119ms로 2.5-flash의 11,969ms와 비교가 안 된다.

다만 **이 실험에서 처음으로 비결정적 판정이 나왔고**, `thinking`을 끌 수 없어 D-061의
설계 전제 하나가 이 모델에는 성립하지 않는다.

## 2. 발견 ① — `budget=0`을 거부하는 모델이 있다

측정을 시작하자마자 68건 전부가 `400 INVALID_ARGUMENT`로 실패했다. 원인을 좁힌 결과
**`gemini-3.5-flash-lite`는 `thinking_budget=0`을 받지 않는다.**

| 설정 | 결과 |
|---|---|
| `thinking_config` 없음 | OK |
| `thinking_budget=0` | **400 INVALID_ARGUMENT** |
| `thinking_budget=512` | OK |
| `thinking_budget=-1` (동적) | OK |

세대별 차이가 아니라 **모델별**이다.

| 모델 | `budget=0` |
|---|---|
| `gemini-2.5-flash` | 지원 |
| `gemini-2.5-flash-lite` | 지원 |
| `gemini-3.1-flash-lite` | 지원 |
| **`gemini-3.5-flash-lite`** | **거부** |
| `gemini-3.5-flash` | 지원 |
| **`gemini-3.6-flash`** | **거부** |

### D-061 설계에 대한 함의

D-061은 **목록에 없는 모델에는 아무것도 싣지 않기로** 했다. 그 판단이 여기서 값을 한다 —
기본값을 `0`으로 뒀다면 `.env`에 이 모델을 넣는 순간 **인텐트 분류 전 요청이 400으로 죽는다.**
조용한 품질 저하가 아니라 전면 장애다.

동시에 D-061의 "1순위는 `budget=0`" 규칙은 **이 모델에 적용할 수 없다.** 채택하려면
예산 표에 `0`이 아닌 값을 넣거나 목록에서 빼야 한다.

## 3. 정확도 — 2.5-flash에 1건 차이

모수는 규칙 정의 65건(19·50·60 제외, 선행 실험과 동일 규약).

| | 2.5-flash `b=0` | 2.5-lite `b=0` | 2.5-lite `b=512` | **3.5-lite 미설정** | **3.5-lite `b=512`** |
|---|---|---|---|---|---|
| **정확도 (65건)** | **64/65** | 57/65 | 60/65 | **63/65** | **63/65** |
| 정확도 (전체 68건) | 64/68 | 57/68 | 61/68 | 63/68 | 64/68 |
| 대조쌍 (12건) | — | 9/12 | 12/12 | 11/12 | 11/12 |
| 지연 중앙값 | 1,588ms | 1,027ms | 2,118ms | **852ms** | **824ms** |
| 지연 p90 | 5,327ms | 1,208ms | 2,621ms | **928ms** | 1,006ms |
| 지연 최대 | 11,969ms | 2,235ms | 2,909ms | **1,119ms** | 1,114ms |

**3.5-lite는 미설정과 `512`가 65건 기준 동일하고 지연도 852 / 824ms로 차이가 없다.**
2.5-lite에서 예산이 57 → 60으로 판정을 크게 바꿨던 것과 다르다. 이 모델에서는 예산을
건드릴 이유가 보이지 않는다.

### 2.5-lite가 무너졌던 7건을 전부 견딘다

선행 실험에서 2.5-lite가 5/5로 틀렸던 대화 맥락 의존 케이스다.

| # | 발화 | 2.5-lite `b=0` | **3.5-lite 미설정 (5회)** |
|---|---|---|---|
| 10 | "다른 곳 보여줘" | MODIFY ❌ | **5/5 ✅** |
| 24 | "무료인 곳으로" | RECOMMEND ❌ | **5/5 ✅** |
| 29 | "주차 가능한 곳" | RECOMMEND ❌ | **5/5 ✅** |
| 33 | "어디가 더 가까워?" | MODIFY ❌ | **5/5 ✅** |
| 41 | "벚꽃 언제 피어?" | INFO ❌ | **5/5 ✅** |
| 59 | "종로구" | RECOMMEND ❌ | **5/5 ✅** |
| 65 | "광화문 근처에서" | RECOMMEND ❌ | **5/5 ✅** |

2.5-lite는 `512`를 실어야 4건만 회복됐는데, **3.5-lite는 아무 설정 없이 7건 전부 맞힌다.**

## 4. 발견 ② — 처음으로 비결정적 판정이 나왔다

68번 "어디가 좋아?"(노출 1)가 5회 중 **1/5**로 흔들린다.

```
68번: RECOMMEND, COMPARE, COMPARE, COMPARE, COMPARE
```

`temperature=0.0`인데도 갈린다. **지금까지 측정한 2.5 계열 4개 조건은 전부 5/5로
결정적이었다.** 이 실험에서 처음 나온 현상이다.

실무적 함의가 두 가지다.

- **§3의 63/65는 낙관적이다.** 68번이 1회 측정에서 우연히 맞은 값이며, 반복하면 대체로
  틀린다. 반복 기준으로 재집계하면 실질 62/65에 가깝다.
- **재현 가능성이 떨어진다.** 회귀 판정 도구로서의 가치가 2.5 계열보다 낮다. 같은 입력에
  같은 답을 요구하는 자리(테스트 고정값 등)에 쓰기 어렵다.

원인은 확인하지 못했다. 모델 내부 샘플링일 수도, thinking의 비결정성일 수도 있다.
`b=512`에서도 흔들리는지는 재보지 않았다(§7).

## 5. 남은 오답 2건

| # | 발화 | 기대 | 3.5-lite (5/5) | 성격 |
|---|---|---|---|---|
| 31 | "처음부터 다시 추천해줘" | MODIFY | RECOMMEND | **기대값 확정 대기** |
| 68 | "어디가 좋아?" | RECOMMEND | 흔들림 (1/5) | 비결정 |

**31번은 순수한 모델 오답이 아니다.** CoT 실험 §8이 "규칙은 있으나 기대값 확정이 필요한
1건"으로 분류해 A 회신을 기다리는 케이스다. 재시작 규칙이 도입되면 기대값이 `RECOMMEND`로
뒤집히고, **그러면 3.5-lite가 맞은 것이 된다.** 그 경우 64/65로 2.5-flash와 같아진다.

즉 **현재의 1건 차이는 기대값 확정 결과에 달려 있다.**

## 6. 판정 — 유망하나 채택 전 확인 필요

| | |
|---|---|
| **강점** | 2.5-flash 대비 정확도 −1건(확정 대기 결과에 따라 동률 가능), 지연 절반, 꼬리 10분의 1. 맥락 의존 판정을 설정 없이 전부 맞힘 |
| **약점** | 판정이 흔들린다(68번 1/5). `budget=0` 불가로 D-061 규칙 하나가 안 맞는다 |
| **판단** | 폴백 교체 후보로는 2.5-lite보다 명백히 낫다. **1순위 교체는 §7을 확인한 뒤에 판단한다** |

이 실험만으로 `.env`를 바꾸지 않는다. 근거가 인텐트 분류 1단계 68건 1~5회에 한정된다.

## 7. 채택 전에 확인할 것

| # | 확인 사항 | 이유 |
|---|---|---|
| 1 | **2단계 조건 추출 품질** | `UserConditions` 15개 필드 추출은 분류보다 어려운 과제다. 1단계 결과가 여기로 일반화된다는 근거가 없다 |
| 2 | **비결정성의 범위** | 68건 전체를 3회 이상 돌려 흔들리는 케이스가 68번뿐인지 확인 |
| 3 | **`b=512`에서도 흔들리는지** | 예산으로 안정화되면 선택지가 하나 는다 |
| 4 | **단가** | 3.5 계열 가격을 확인하지 않았다. 지연이 줄어도 비용이 오르면 판단이 달라진다 |
| 5 | **31번 기대값 (A 회신)** | 이 하나로 "1건 차이"가 "동률"이 된다 |

## 8. 한계

- **1단계 분류만 봤다.** 선행 실험들과 같다.
- **68건 1회 + 9건 5회.** 3.5-lite의 비결정성이 드러난 이상, 1회 측정 수치의 신뢰도는
  2.5 계열보다 낮다.
- **`b=512` 반복 측정은 안 했다.**
- **모델 스냅샷 고정 불가**, 케이스 68건 — 선행 실험과 같은 한계다.

## 9. 재현 방법

```bash
cd backend
OUT=test_results/model_35_flash_lite_2026-08-12

python -m scripts.measure_intent_thinking --model gemini-3.5-flash-lite \
  --repeat 1 --delay 1.0 --tag lite35_bdefault --out-dir $OUT
python -m scripts.measure_intent_thinking --budget 512 --model gemini-3.5-flash-lite \
  --repeat 1 --delay 1.0 --tag lite35_b512 --out-dir $OUT

python -m scripts.measure_intent_thinking --model gemini-3.5-flash-lite \
  --repeat 5 --delay 1.0 --only 10,24,29,31,33,41,59,65,68 \
  --tag lite35_bdefault_repeat --out-dir $OUT
```

`--budget 0`은 이 모델에서 `400 INVALID_ARGUMENT`가 된다(§2).

`gemini-3.5-flash-lite`는 `_INTENT_THINKING_BUDGETS`(D-061)에 없으므로 `--budget` 생략이
곧 모델 기본값이다. 목록에 추가하면 이 재현 명령의 의미가 바뀐다.

비교 대상인 2.5 계열 수치는 `../fallback_model_ab_2026-08-12/`와
`../fallback_thinking_2026-08-12/`에 있다. 케이스 정의는
`../intent_cot_2026-08-11/intent_classification_cases_2026-08-11.csv`.
