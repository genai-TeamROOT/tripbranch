# 서비스 지원 지역 경계

MVP 지원 범위(서울 종로구) 밖의 위치를 판정하는 데 쓰는 폴리곤이다.

| 파일 | 내용 |
| --- | --- |
| `jongno.geojson` | 종로구 경계 1개 Feature (MultiPolygon, 좌표 194개) |

## 출처와 라이선스

- 원자료: KOSTAT 센서스용 행정구역경계 (통계청 SGIS)
- 경유: <https://github.com/southkorea/southkorea-maps> — `kostat/2018/json/skorea-municipalities-2018-geo.json`
- 라이선스: `KOSTAT: Free to share or remix.`
- 기준 연도 2018, 추출일 2026-08-04

같은 내용을 파일 최상위 `attribution` 멤버에도 넣었다. 데이터와 출처가 떨어지면 나중에
어느 쪽이 근거인지 추적할 수 없어서다. GeoJSON은 최상위 임의 멤버를 허용한다.

## 왜 역지오코딩이 아니라 폴리곤인가

네이버 Reverse Geocoding은 별도 구독 상품이라 현재 키로는 403이 돌아온다. 구독하더라도
판정 하나 때문에 모든 요청에 외부 호출과 장애 지점을 하나 더 얹게 된다. 행정구역 경계는
거의 변하지 않는 정적 데이터라 매 요청 API로 물어볼 성질이 아니다.

경계 상자(bounding box)는 종로구가 남북으로 길쭉하고 북악산 쪽으로 굽어 있어 맞지 않는다.
실제로 상자에 여유를 주면 중구 명동·서울역이 안쪽으로 들어온다.

## 정밀도

활성 장소 844건으로 검증했을 때 폴리곤 밖으로 판정된 것은 2건이다(0.24%).

- 북악산 숙정문 — 북악산 능선 경계
- 2026년 강제동원 희생자를 기리는 유족·시민 어울림행사 — 청계천 남쪽 경계

둘 다 경계선에 붙어 있어 2018년 경계의 정밀도 한계에 걸린다. 저장소에서 해석된 장소는
이미 종로구로 등록된 것이라 판정을 생략하므로 실제 영향은 없다(D-044).

## 갱신

행정구역이 개편되면 위 저장소에서 최신 연도 파일을 받아 종로구 Feature만 다시 추출한다.
전체 파일은 18MB라 저장소에 넣지 않는다.
